# Практика: оновити рядок за ключем заявки

AI Insider · Оновлено 2026-10-05
Гайд: https://www.aiinsider.it.com/insights/n8n-google-sheets

Навчальне завдання на синтетичних даних. Не результат клієнтського проєкту.

Підготуйте тестовий лист із заголовками event_id, email, status і updated_at. Номер рядка не є стабільним ключем: сортування або вставка рядка змінює його.

## Порядок роботи

1. Підключіть тестову таблицю з мінімальним доступом. Запишіть її ID та назву листа в конфігурації сценарію.
2. Перед оновленням знайдіть event_id. Для відсутнього ключа створіть рядок, для наявного змініть тільки дозволені поля.
3. Значення updated_at зберігайте у визначеному часовому поясі або UTC. Телефони й ідентифікатори не перетворюйте на числа з втратою нулів.
4. Повторіть заявку після сортування таблиці. Потім перевірте обмеження API й сценарій затриманої відповіді.

## Вхідні дані

```json
{"event_id":"lead-001","email":"demo@example.com","status":"new","updated_at":"2026-10-05T10:00:00Z"}
```

## Перевірка

| Вхід або ситуація | Очікувана поведінка |
| --- | --- |
| Новий ключ | Один новий рядок |
| Існуючий ключ | Оновлений потрібний рядок |
| Сортування листа | Пошук за event_id лишається коректним |

## Межі прикладу

Таблиця зручна для малого пілота, але пошук перед append не забезпечує атомарності при паралельних запусках. Для критичних процесів використовуйте сховище з унікальним ключем.
