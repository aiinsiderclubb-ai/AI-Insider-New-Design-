# Практика: бот приймає заявку й підтверджує її один раз

AI Insider · Оновлено 2026-10-05
Гайд: https://www.aiinsider.it.com/insights/n8n-telegram-bot

Навчальне завдання на синтетичних даних. Не результат клієнтського проєкту.

Зберіть навчальний маршрут Telegram Trigger → перевірка повідомлення → нормалізація → тестова таблиця → підтвердження. Для першої перевірки достатньо одного дозволеного chat_id.

## Порядок роботи

1. Створіть окремого тестового бота й збережіть токен у credential. Підключіть Telegram Trigger за актуальною інструкцією.
2. Відокремте команди від звичайного тексту. /start пояснює можливості; порожнє або невідоме повідомлення просить уточнення.
3. Збережіть update_id як ключ події та перевірте повтор перед записом. Після успішного запису надішліть підтвердження.
4. Спробуйте повідомлення від недозволеного користувача та повторну доставку. Звичайний текст не повинен змінювати права доступу.

## Вхідні дані

```json
{"update_id":101,"message":{"chat":{"id":12345},"text":"Потрібен аудит процесу"}}
```

## Перевірка

| Вхід або ситуація | Очікувана поведінка |
| --- | --- |
| Дозволений chat_id | Один запис, одне підтвердження |
| Повтор update_id | Без другого запису |
| Невідома команда | Пояснення; жодної зовнішньої дії |

## Межі прикладу

Приклад payload синтетичний. Підставте власний chat_id та перевірте HTTPS і конфлікти webhook. Токен не можна додавати в export або скриншоти.
