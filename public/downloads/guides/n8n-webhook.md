# Практика: контракт для POST-заявки

AI Insider · Оновлено 2026-10-05
Гайд: https://www.aiinsider.it.com/insights/n8n-webhook

Навчальне завдання на синтетичних даних. Не результат клієнтського проєкту.

Визначте контракт до налаштування nodes: які поля приймає endpoint, хто має доступ і коли відповідь вважається успішною. Тестовий URL і опублікований URL мають різні режими роботи.

## Порядок роботи

1. Налаштуйте POST і автентифікацію, доступну у вашій версії. Для тесту запустіть очікування події та надішліть синтетичний JSON.
2. Перевірте обов’язкові поля, типи й довжини. Повертайте зрозумілу помилку до будь-якого запису в CRM.
3. Визначте значення success: подію прийнято в чергу чи вже записано. Не обіцяйте завершену операцію, якщо виклик тільки почався.
4. Повторіть event_id, неправильний метод і запит без авторизації. Для production перевірте URL, режим публікації та налаштування reverse proxy.

## Вхідні дані

```json
{"event_id":"webhook-001","email":"demo@example.com","source":"contact_form"}
```

## Перевірка

| Вхід або ситуація | Очікувана поведінка |
| --- | --- |
| POST з валідними полями | Очікуваний success-код |
| Немає авторизації | Відмова до обробки |
| Повторна доставка | Один бізнес-результат |

## Межі прикладу

Код 200 не доводить правильність запису. Перевіряйте кінцеву систему й не повторюйте небезпечну дію після timeout без перевірки результату.
