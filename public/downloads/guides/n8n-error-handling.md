# Практика: відтворити збій CRM і безпечно повторити

AI Insider · Оновлено 2026-10-05
Гайд: https://www.aiinsider.it.com/insights/n8n-error-handling

Навчальне завдання на синтетичних даних. Не результат клієнтського проєкту.

Почніть з тестової інтеграції та навмисно неправильного credential. Мета — отримати зрозумілий alert, виправити доступ і повторити операцію без дублювання вже завершених дій.

## Порядок роботи

1. Призначте Error Trigger workflow та канал повідомлення відповідальному. Передайте лише безпечні відомості: workflow, failed node, execution і ключ заявки.
2. Відокремте тимчасовий збій API від помилки даних. Перший може дозволяти обмежений retry, другий потребує виправлення payload.
3. Перевірте, які попередні кроки вже виконані. Перед повторною відправкою звірте статус у кінцевій системі.
4. Запишіть runbook: де відкрити execution, хто може змінити доступ і як перевірити відновлення. Перевірте поведінку і ручного, і автоматичного запуску.

## Перевірка

| Вхід або ситуація | Очікувана поведінка |
| --- | --- |
| Помилка доступу | Alert містить failed node і execution |
| Невалідні дані | Без нескінченного retry |
| Повтор після виправлення | Жодного дубльованого запису |

## Межі прикладу

Режими виконання й запуск error workflow відрізняються; звірте їх з документацією своєї версії. Alert без призначеного відповідального не є процесом відновлення.
