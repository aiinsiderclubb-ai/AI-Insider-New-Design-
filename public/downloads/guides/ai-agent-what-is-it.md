# Практика: відрізнити агента від чатбота

AI Insider · Оновлено 2026-10-05
Гайд: https://www.aiinsider.it.com/insights/ai-agent-what-is-it

Навчальне завдання на синтетичних даних. Не результат клієнтського проєкту.

Візьміть звернення «Де моє замовлення?». Чатбот може пояснити загальні правила. Агент, якому це дозволено, перевіряє конкретне замовлення через інструмент і повертає статус. Він не повинен приймати номер з тексту як доказ права доступу.

## Порядок роботи

1. Опишіть доступний інструмент get_order_status та поля відповіді. Не відкривайте агенту універсальний доступ до бази.
2. Перед викликом перевірте автентифікацію та належність замовлення користувачу. Ця перевірка має бути незалежною від рішення моделі.
3. Додайте відповідь для недоступного API: повідомити про затримку, створити звернення, передати оператору.
4. Перевірте спробу скасування чи повернення грошей. Такі дії потребують окремого дозволу й підтвердження.

## Перевірка

| Вхід або ситуація | Очікувана поведінка |
| --- | --- |
| Власне замовлення | Статус із джерела |
| Чуже замовлення | Доступ відхилено |
| API не відповідає | Без вигаданого статусу; передача людині |

## Межі прикладу

Приклад описує архітектуру, а не готову інтеграцію магазину. Якість агента вимірюється успішними дозволеними діями та коректними відмовами, не довжиною відповіді.
